# GarmentCode の型紙を取り込む

[GarmentCode](https://github.com/maria-korosteleva/GarmentCode) が出す
`*_specification.json`(平面の縫製パターン)を Blender に読み込み、
**Blender 標準の Cloth で縫い合わせられる状態**にするための機能。

`costume/`(spec から衣装メッシュを直接生成する)とは無関係の別系統。
あちらは「封筒(envelope)としての衣装」を作る。こちらは
**平面パーツ + 縫合スプリング**で、シミュレーションに実際に縫わせる。

---

## 実装しないもの(Blender 標準で足りる)

CLAUDE.md の最重要方針どおり、以下は**このプラグインに実装していない**。

| やりたいこと | Blender 標準のどこ |
|---|---|
| 重力・剛性・縫合力・自己衝突などの調整 | プロパティ > 物理演算 > **クロス** |
| シミュレーションのベイク | プロパティ > 物理演算 > クロス > **キャッシュ > ベイク** |
| 体との衝突 | 素体の複製に **Decimate** + **Collision** モディファイア |
| 布に厚みを付ける | **Solidify** モディファイア |
| スムーズシェード / 細分化 | **Shade Smooth** / **Subdivision Surface** |

実装したのは3つだけ:

1. **spec の取り込み**(平面パネル -> 縫合エッジ付きの1メッシュ・3D 配置)
2. **袖・カフの腕軸への自動センタリング**
3. **縫い目の溶接**

どれも「標準機能では手が届かない」ものだけを残した結果。

### なぜ溶接だけは自前なのか

- `メッシュ > マージ > 距離で` は**全体マージ**。前中心・後中心のパネル対は
  spec 上まったく同じ座標を共有しているので、0.001cm でも別パネル同士が
  溶接されて面コンポーネントが 16 -> 12 に減る(参照実装の実測)
- Weld モディファイアの `CONNECTED` モードは「エッジで繋がった**距離しきい値以内**の
  頂点」を溶接する。縫合ギャップは 0.3〜1.0cm に収束する一方、素の三角形の辺は
  約 1.5cm。閉じ切っていない縫い目を拾えるしきい値では**本物の辺まで潰れる**

このプラグインの溶接は「**面を持たない孤立エッジ = 縫合エッジ**で結ばれた頂点だけを、
距離に関係なく連結成分ごとに1点へまとめる」。距離ではなく繋がりで決めるので、
座標が一致しているだけの別パネルは原理的に巻き込まれない。

## 手順

1. **シーンを cm にする。** シーンプロパティ > 単位 > 単位スケール `0.01`。
   GarmentCode の出力は cm なので **1 BU = 1cm で無変換(1:1)**に置く。
   スケールは毎回シーンから読んで確かめ、0.01 でなければ警告を出す(ハードコードしない)
2. 素体メッシュを選択して(=アクティブにして)
   **サイドバー N > My Plugin > GarmentCode 型紙 > `GarmentCode パターンを取り込む`**
3. ファイルブラウザで `*_specification.json` を選ぶ。右のサイドバーで
   目標エッジ長(既定 1.5cm)と素体を確認する。**素体は読むだけで一切変更しない**
4. `GarmentCode` コレクションに `GC_Cloth` ができる。INFO 欄に
   パネル数 / 頂点数 / 縫合エッジ数 / 初期ギャップ / センタリング量が出る
5. **体のコリジョンを用意する**(標準機能):
   素体を複製 -> Decimate(比率を下げて 3000 三角形くらい) -> Collision モディファイア。
   厚み(外側/内側)は RNA 上限の 1.0 まで。**元の素体には付けない**
   (素体の設定を壊すし、フル解像度との衝突は遅い)
6. `GC_Cloth` にクロスを付けて回す(プロパティ > 物理演算 > クロス)。
   縫合(`Sewing`)を有効にすること。孤立エッジがそのまま縫合スプリングになる
7. 形が決まったフレームで **`縫い目を溶接`**。現在フレームの評価済み形状を
   複製して縫合ペアだけを溶接した新しいオブジェクトができる(元は無変更)

### cm シーンでのクロスの注意(実装はしないが罠なので書いておく)

参照実装の実測メモから。数値はこのプラグインでは持たない — 標準 UI で設定する。

- Blender のソルバは `scale_length` に関係なく「1 BU = 1m」で重力を計算するので、
  cm シーンでは重力が 1/100 になる。**`シーンの重力` ではなく、クロスの
  `フィールドウェイト > 重力` を上げて補正する**(シーン全体を汚さない)。
  実測上の上限は 10。100 では体を貫通して落下した
- 最初の 40〜70 フレームは重力 0 にして、**先に無重力で縫い目を閉じる**
  (GarmentCode 本家の `zero_gravity_steps` と同じ考え方)
- `圧縮剛性` を上げてはいけない。縫合の収縮と喧嘩して縫い目が閉じなくなる
- `縫合の最大力` を 0(無制限)にしてはいけない。55cm 離れた縫合で発散する
- 縫合スプリングは**力**なので 0 にはならない。0.3〜1.0cm で落ち着く。
  だから最後に溶接の工程が要る

## 袖・カフの自動センタリング — なぜこれが要るのか

★ この取り込み器でいちばん重要な処理。

**袖を「腕をよけるまで上に持ち上げる」だけでは失敗する。**
縫合スプリングが筒を閉じるとき、筒は**自分自身の重心**に向かって収束するので、
腕が筒の外に残り、袖がずり落ちる。参照実装は3回のシミュレーション失敗でこれを
突き止めた。証拠はカフの `|x|` が **55 -> 38 -> 21** と移動していったこと。

正解は、袖・カフの各コンポーネントを腕の軸に対して
**軸と直交する2方向の両方で**中心合わせすること。参照データでの実測オフセットは
**袖 Y+6.35 / Z+13.11、カフ Y+6.78 / Z+3.20**。センタリング後は 453 本の縫い目が
すべて閉じ(最大 0.99cm)、どの断面でも腕が筒の内側にあり、カフの移動量は
1.6cm に収まった。

### 決め方

数値はハードコードしない。取り込みのたびに素体から測り直す。

1. **手足パネルを拾う。** spec の `panel["label"] == "arm"`、または名前に
   `sleeve` / `cuff` / `arm` を含むもの
2. **縫合で繋がった塊にまとめる**(Union-Find)
3. **支配軸(最長辺)方向に重なる区間ごとに割る。** 袖とカフは縫合で繋がっているが
   軸方向には別の区間を占めるので分かれる。実測でも袖とカフには**別々の**
   オフセットが必要だった(Z で 13.11 と 3.20)
4. 最長辺 / 2番目の辺 が 1.15 未満なら筒とみなさず飛ばす
5. **クラスタのスパンのうち体から遠い側の半分**で素体の断面中心を測る。
   体に近い側は胴体が混ざって中心がずれる。区間を最大8スラブに割り、
   各スラブの**中央値**を取ってスラブ間で平均する(指先などの外れ値に強い)
6. クラスタの現在の中心との差を並進量にする。40cm を超える値は異常として適用しない

### 素体は絶対に変更しない

センタリングの測定に使うのは素体の**評価済みメッシュを読んだ座標だけ**
(`build.body_sample_points`)。素体にモディファイアも頂点グループも足さない。

なお参照実装は測定点を「デシメート前のフル解像度」から取っていた。
デシメート後(約3000三角)だとカフのような短い区間でサンプルが数点しか入らず、
左右で 0.7cm 以上ぶれる。このプラグインはコリジョンプロキシを作らない
(標準機能に任せる)ので、そもそもフル解像度の素体から測っている。

## 実装のかたち

`costume/` と同じく **bpy の境界で割る**。純粋関数は pytest から直接テストできる。

| モジュール | bpy | 中身 |
|---|---|---|
| `spec.py` | 非依存 | JSON の読み込みと検証(`SpecError`)、単位・座標系の警告 |
| `curves.py` | 非依存 | circle / quadratic / cubic のテッセレーション、等弧長リサンプル |
| `panel_mesh.py` | 非依存 | 外形の巡回、六方格子の内部点、CDT 入力の組み立て |
| `transform.py` | 非依存 | GarmentCode -> Blender の行列と位置(行タプルで返す) |
| `topology.py` | 非依存 | Union-Find、面コンポーネント数、溶接グループ |
| `limbs.py` | 非依存 | 手足クラスタの検出と並進量の計算 |
| `stitches.py` | 非依存 | ステッチの頂点対応付け(向きの選択・自己ループ除去) |
| `build.py` | **依存** | `delaunay_2d_cdt`・オブジェクト/コレクション/頂点グループ生成 |
| `weld.py` | **依存** | `bmesh.ops.weld_verts` |

`delaunay_2d_cdt` は `mathutils` にあるので bpy 側。
`build` / `weld` は **トップレベルで import してはいけない**
(`operators.py` の `execute()` の中で遅延 import する)。

### 曲率の読み方

`properties.curvature_coords == "relative"` のとき、制御点は**エッジ座標系**で与えられる:

```
p = start + u * e + v * perp(e),   perp(e) = (-e_y, e_x)
```

`e` は正規化していないので u も v も `|e|` 倍の長さになる。

- **quadratic / cubic**: 上の式で制御点をパネル座標に写して de Casteljau
- **circle**: params は `[radius, large_arc, right]`。GarmentCode は
  「エッジの中点を (0.5, cy) に置いた円弧」で曲率を表すので
  `rel_rad = (0.25 + cy^2) / (2|cy|)` を逆に解いて `cy` を復元する。
  `large_arc=1` で大きい方の根、`right=1` で符号が負。
  **復元した半径は spec の radius と 1e-9 以内で一致する**(テストで検査している)。
  サンプルは弧の角度について等間隔(= 弧長等間隔)

### メッシュ化

境界を目標エッジ長(1.5cm)で等弧長リサンプルし、内側に六方格子
(行間 `sqrt(3)/2`、境界から `0.62 x 目標`)を撒いて、外形を拘束にした
`delaunay_2d_cdt`(`CDT_INSIDE`)に掛ける。

**重複頂点のマージはパネル内だけ。** 全体マージは厳禁
(上の「なぜ溶接だけは自前なのか」と同じ理由)。取り込み後に
**面コンポーネント数 != パネル数**なら警告を出す。減っていたら
どこかで別パネルが溶接されている。

### ステッチの対応付け

2本の境界エッジの頂点を**正規化弧長**で対応付ける。踏む罠が2つ:

- **向き。** 順・逆の両方でマッチを取り、頂点間距離の総和が短い方を採る
  (参照データでは 40 本中 **40 本**で B 側の反転が必要だった)
- **ダーツ先端の自己ループ。** 2本のエッジが同じ頂点を共有するので `i == j` の
  ペアができる。無意味なので捨てる(参照データで 8 件)

マッチは両方向の最近傍の**和**を取る。片方向だけだと、点数の少ない側の頂点に
スプリングが1本も付かないことがある。

## 参照データでの期待値

`blouse_final_specification.json`(16パネル / 40ステッチ)を目標エッジ長 1.5cm で
取り込んだときの参照実装の実測:

| 項目 | 値 |
|---|---|
| 頂点 | 約 3331 |
| 縫合エッジ | 453 |
| 面コンポーネント | 16(= パネル数) |
| 面積誤差 | 0% |
| 平均エッジ長 | 1.57cm |
| 向き反転したステッチ | 40 / 40 |
| 飛ばした自己ループ | 8 |

テストのフィクスチャ `tests/data/garmentcode_right_half_specification.json` は
この spec の**右半身だけ**(5パネル / 9ステッチ)を切り出したもの。
circle / cubic の曲率、ダーツ先端の自己ループ、袖+カフの手足クラスタが全部入っている。

## まだ無いもの

- **パネルを1枚ずつ別オブジェクトとして出す経路**(形の確認用。シミュには不要)
- **UV**。`costume/` と違って解析的な UV を張っていない。必要なら標準の
  UV 展開(縫合エッジをシームにすると素直に開く)
- **マテリアル**。素のメッシュで出る
- **パンツの脚のセンタリング**。`limbs.LIMB_NAME_KEYWORDS` に `pant` / `leg` を
  足せば動く見込みだが**未検証**
